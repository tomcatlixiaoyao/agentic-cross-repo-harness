# 可选的 Codebase Memory 集成

[Codebase Memory MCP](https://github.com/DeusData/codebase-memory-mcp) 与本 Harness 解决的是 AI 辅助变更的不同环节：

- Codebase Memory 在本地建立代码结构模型，用于发现调用链、路由、依赖和潜在影响；
- Harness 记录经过人工确认的仓库权限、契约归属、验证、回滚和恢复状态。

代码分析结果只是证据，不是授权。安装或查询 Memory 工具不能扩大 ExecPlan 的写入边界。

## 推荐流程

```text
需求
  -> Harness 仓库注册表和 ExecPlan 草案
  -> 本地代码图谱与影响分析
  -> 人工确认建议的仓库和路径
  -> 冻结 ExecPlan 写入范围
  -> 实现
  -> 各仓库独立验证
  -> 记录集成证据和恢复状态
```

## 安全接入

1. 安装二进制或 MCP 服务前，审查上游源码、Release 校验值、安装行为和团队安全策略。
2. 保持本地处理。不要公开私有仓库的图数据库、源码片段、内部路由或自动生成的架构摘要。
3. 将索引限制在目标工作区。Codebase Memory 提供 `CBM_ALLOWED_ROOT`，用于限制允许请求的仓库路径。
4. 审查对用户级 AI 配置和 hooks 的修改。完成安装不等于获得业务仓库写入权限。
5. 只索引任务所需的已注册仓库，并通过工具支持的忽略规则排除生成文件、凭据和本地配置。

安装时应遵循上游最新说明，不要把未经版本固定的安装命令复制进团队执行计划。

## 建议收集的证据

冻结 ExecPlan 前，可以用结构查询回答：

- 哪个 Provider 路由或处理器拥有目标行为？
- 哪些调用方和 Consumer 仓库依赖相关符号或契约？
- 修改是否跨越包、服务或仓库边界？
- 哪些测试与受影响代码直接相关？

计划中只记录精简且可审查的证据：

```markdown
| 证据 | 内容 |
| --- | --- |
| 仓库版本 | 不可变的 commit id |
| 索引新鲜度 | 在该版本完成索引 |
| 限定符号 | Provider 中的限定符号名称 |
| 建议影响路径 | 已审查的路径列表 |
| 人工决策 | 接受、缩小或拒绝，并说明原因 |
```

不要把本地 SQLite 图谱或大量源码衍生内容提交到控制仓库。

## 权限边界

Memory 结果可以建议扩大或缩小影响范围，但不能自动改变以下 Harness 规则：

- 未注册仓库仍然不在范围内；
- 每个已注册仓库仍必须有一行 ExecPlan；
- 允许写入的路径必须经过人工确认；
- Provider 契约真相仍位于 Provider 仓库；
- 验证命令仍归各仓库所有，Harness 校验器不会执行；
- 发布、部署、权限修改和破坏性操作仍需单独确认。

如果图谱结果与源码、生成代码、仓库规则或运行时行为冲突，应停止并解决差异，不能把推断关系当成权威事实。

## 失败与降级

Codebase Memory 是可选能力。如果它不可用、索引过期、语言不支持或团队策略禁止使用：

1. 使用常规仓库检查和语言原生工具继续分析；
2. 将结构分析标记为不可用或降级；
3. 不能因为索引成功就宣称仓库验证或集成验证成功；
4. 保留恢复点和下一项明确的调查动作。

即使没有 MCP、后台进程、图数据库或特定 AI 编程工具，Harness 仍然可以独立使用。
